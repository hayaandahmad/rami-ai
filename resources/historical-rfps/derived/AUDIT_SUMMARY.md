- `questionId` (when from Q&A)

- `status` (`Answered` / `TBC` / …)

- `provenanceClass` = `REFERENCE` (never `EXTRACTED` into live project automatically)

## Recommended future architecture (do not build now)

PostgreSQL remains SoT. Minimal justified entities:

1. **`historical_rfp_documents`** — manifest row, PDF path, hashes, kinds  
2. **`historical_question_answers`** — one row per Q&A cell (questionId, answer, status, sourceLocator)  
3. **`historical_rfp_sections`** (optional) — PDF section headings / page ranges when chunked  
4. **`knowledge_chunks`** — later text units with FK to document + locator  
5. **`embeddings`** / pgvector — **only after** chunk schema + provenance are stable  

Keep **strict separation** from `projects`, `project_facts`, `messages`, `project_section_contents`.

Ingestion pipeline concept: Excel → `historical_question_answers`; PDF → sections/chunks → embeddings; retrieval returns REFERENCE with citation UI.

## Inconsistencies / caveats

- 3 datasets lack source PDFs (SSC, NUR, Connectivity).  
- ITAS/RFP17 PDFs were adjacent Downloads matches — included and noted in manifest.  
- Cover-title typos in source RFPs retained in Excel answers (e.g. “REEGENIRING”) — do not “fix” source.  
- `Not applicable` is common on frameworks for software-centric questions — readiness packs must honor N/A.  
- Suggested Additions IDs collide across domains (same `13.1` different wording) — future packs need namespaced IDs.  
- Combined “all fields strong somewhere” ≠ every RFP fills every Field well.
